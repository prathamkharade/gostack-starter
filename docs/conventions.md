# Code conventions

## Layout of a feature (`internal/<plural>/`)
- `repo.go` – model struct, `listing.Spec`, SQL (pgx), exporter registration.
- `handlers.go` – `Routes(...)` + handlers. No SQL here.
- `views.templ` – pages and fragments for this feature only.
Shared UI goes to `internal/views/components`; full-page shells to `internal/views/layouts`.

## Go
- Standard library first. `context.Context` first param. Return errors, wrap with `fmt.Errorf("x: %w", err)`.
- Handlers return `fiber.NewError(code, "message for humans")` for expected failures; plain `err` for bugs (→ 500, logged).
- IDs are UUIDv7 strings generated by Postgres (`DEFAULT uuidv7()`).
- Times: `timestamptz`, compare in SQL with `now()`.
- Never build SQL with user input; dynamic lists go through `listing.Spec` (whitelists).
- Logging: `slog` with key/value pairs; never log PII or secrets.
- Tests: table-driven unit tests next to code; DB tests behind `//go:build integration`.

## SQL / migrations
- File `NNNN_description.sql`, forward-only. One concern per file. Include indexes for every WHERE/ORDER BY used.
- Constraints in the DB (CHECK, NOT NULL, FK) as the last line of defence.
- Owned rows: `owner_id … ON DELETE CASCADE`.

## templ / htmx / Alpine
- Components take explicit params; read per-request data via `httpx.VD(ctx)`.
- URLs in `href`/`action`/`hx-*` are built from trusted strings (`"/items/" + it.ID`).
- htmx 4: put `:inherited` on attributes meant for descendants; colon event names; `hx-status:4xx` for per-element overrides.
- Alpine (CSP build): `x-data="name"` registered in `static/js/app.js`; markup uses properties and method
  names (`x-on:click="toggle"`), no arrow functions, no globals, no template literals.
- No inline `<script>`/`style=""`; JSON-LD via `seo.JSONLDScript` is the only allowed script block (not executable).

## Naming
Packages: short, plural for features (`items`). Routes: plural nouns (`/items`, `/items/:id/edit`),
POST for all mutations (forms work without JS). Templ components: `PascalCase` exported, `camelCase` private helpers.

## Commits
Small, focused, `make check` green. Conventional prefix (`feat:`, `fix:`, `docs:`, `chore:`).
Record significant choices as ADRs in `docs/decisions/NNNN-title.md` (context, decision, consequences – 10 lines).
